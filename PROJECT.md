# CareerFox

**AI-powered job search that saves you time in your specific field.**

Pick your field (a "niche"), and CareerFox gathers jobs daily, filters out the noise, and uses a self-hosted LLM to read each promising job in full and score how well it fits you. No endless scrolling.

## Status

Concept **and architecture FINALIZED and validated in the playground** (real API tests in Docker) — coverage, accuracy, scale, and end-to-end (Mina & Tom, with links) all checked. **No application code yet — waiting on the green light.**

## v1 scope

- **Users:** skilled but unemployed professionals seeking the right role — a key segment is internationals/expats in Germany (broadly bilingual, often stronger in English than German).
- **Niches (start with 2, to test accuracy across role + region):**
  1. **UX Designer — Munich region**
  2. **Fullstack Developer — Bodensee / Lake Constance region**
- **Input:** upload **CV** + create a niche → role, **place** (On-site Munich / Remote-DE / Remote-EU), keywords.
- **Match card:** fit score + short "why it fits" + **language tag (DE/EN)** + apply link.
- **Cover letter:** generated by AI **on-demand only** (button per job) — never for all jobs.
- **No thumbs up/down.** Personalization comes from the **CV**, not from clicking.
- **Broaden option:** when a niche returns too few matches, offer to relax filters (mid-level, nearby cities, wider remote) — small niches can be tiny (e.g. junior UX Munich ≈ 2 jobs).
- **Rationale language:** English by default, user-selectable German later; job postings kept in their original language.

## User flow

```
Sign up → upload CV
  → create niche: role + place (On-site Munich / Remote-DE / Remote-EU) + keywords
  → CareerFox runs daily in the background
  → dashboard: ranked matches
       card = fit score + "why it fits" + DE/EN tag + [Apply] [Write cover letter]
  → if too few matches: [Broaden search] → relax level / nearby cities / wider remote
```

## Architecture (layered)

**Source layers** — **ATS-first** (validated: volume feeds are mostly noise for niche roles). Each layer is a pluggable **adapter** → one common schema; a job is kept from the *highest* layer it appears in, then deduped.

```
L1  ATS feeds     Personio / Greenhouse / Lever / Ashby / SmartRecruiters / Workable / Recruitee  ← PRIMARY (full text)
L2  Remote feeds  WeWorkRemotely / Jobicy / Remotive   ← OPTIONAL, only for remote-heavy niches (noisy)
L3  Bundesagentur discovery / names only (no descriptions)
L4  Careers-page  best-effort, for companies on no known ATS
```

**Pipeline** — every job flows through:

```
enumerate → poll → normalize → dedup → filter → match → store → serve
```

| Stage | What it does |
|---|---|
| **enumerate** | Build the company universe from **Common Crawl** (harvest ATS company tokens). |
| **poll** | Read each company's public feed daily — no auth, full descriptions. |
| **normalize** | Map every source to one schema `{source, company, title, location, remote, description, url, source_id, posted_at}`. |
| **dedup** | Fuzzy key `normalize(company + title + location)` — sources share no common id. |
| **filter** | Apply the niche: **location first (cheap)**, then role keywords. |
| **match** | LLM (`qwen2.5:14b`) reads the top candidates → fit score + rationale (+ DE/EN tag). *No embeddings needed for v1 — the keyword/location filter narrows enough; `qwen3-embedding:8b` is ready if candidate pools get large.* |
| **store / serve** | Postgres + pgvector → FastAPI API → Next.js dashboard. |

**Runtime components** (all in Docker Compose; nothing runs on the host):

| Component | Tech | Role |
|---|---|---|
| `web` | Next.js | Dashboard |
| `api` | FastAPI | REST API |
| `worker` | Python | Enumerate, poll, filter, match (scheduled) |
| `db` | Postgres + pgvector | Jobs, companies, niches, users, matches, embeddings |
| `keycloak` | Keycloak | User login (OIDC); FastAPI verifies its tokens |
| LLM | Self-hosted OpenWebUI + Ollama (external) | Reads full descriptions, scores fit, writes cover letters |

## Tech stack

- **Backend:** FastAPI · SQLAlchemy 2 + Alembic · Pydantic v2 · httpx (async) · lxml (Personio XML) · APScheduler · pymupdf (CV PDFs)
- **Frontend:** Next.js + TypeScript · Tailwind CSS + shadcn/ui · TanStack Query
- **Data / AI:** Postgres + pgvector · Ollama (self-hosted) — `qwen2.5:14b-instruct` (match + cover letters); `qwen3-embedding:8b` available (embeddings not needed for v1)
- **Auth:** Keycloak (self-hosted, OIDC) — Next.js logs in, FastAPI verifies tokens
- **Infra / tooling:** Docker Compose · uv (Python deps) · pnpm (Node deps) · pytest + Playwright
- **Scale path:** Celery + Redis if the scheduler ever needs parallelism/retries

## Company finder & radar

- **Finder:** the company universe is enumerated from **Common Crawl** (ATS URL patterns) — not from job boards. This is the engine; Bundesagentur/IHK are at most thin name-supplements.
- **Radar is automatic:** we hold the whole universe and poll it daily, so a company that is silent today but posts next week is caught the next day.
- **Honest floor:** a company that posts *nowhere machine-readable* (no ATS/feed) stays invisible. Unavoidable, and small for tech niches.

## Matching pipeline

A funnel that spends LLM time only where it matters:

1. **Location filter (cheap)** — On-site Munich / Remote-DE / Remote-EU. Done *before* the LLM.
2. **Role + keyword filter** — narrows to niche candidates.
3. **Embedding rank** — *not needed for v1* (the cheap filter already narrows to a few dozen; validated with Mina/Tom). `qwen3-embedding:8b` is live on the server and can slot in if candidate pools grow large.
4. **LLM deep read** — self-hosted model reads full descriptions of the top ~20–40 → fit score + "why it fits" + DE/EN tag.

Key: the cheap filter is shared across users/niches; the LLM only ever sees a few dozen candidates per niche. **Scoring uses each user's CV**, falling back to niche criteria when there's no/unreadable CV.

## Scheduling

```
17:00 Europe/Berlin  →  enumerate (periodic) → poll → normalize → dedup → filter → match → store
```

- **v1:** APScheduler in the `worker` — one cron trigger, env-driven (`SCHEDULE_CRON`, `TZ=Europe/Berlin`).
- **Scale path:** Celery + Redis + Beat if parallelism/retries are needed.
- Poll is shared across all niches; only the LLM step is per-niche.

## LLM

- **Serving:** self-hosted OpenWebUI backed by Ollama.
- **Matcher:** `qwen2.5:14b-instruct` (validated on German/English fit-scoring). Fast tier: `qwen2.5:7b-instruct`.
- **Embeddings:** not needed for v1 (cheap filter suffices). **`qwen3-embedding:8b`** is live on the server (plus tiny `embeddinggemma:300m`) — slot in only if candidate pools grow large.
- **Integration note:** call the native `/ollama/api/chat` endpoint with `"format":"json"` — the OpenAI passthrough is disabled on the server.

## Data sources (ATS-first)

**Layer 1 — ATS direct feeds (PRIMARY; full text, free, no auth):**
- **Personio** — `{company}.jobs.personio.de/xml` · **Greenhouse** — `boards-api.greenhouse.io/v1/boards/{company}/jobs?content=true`
- **Lever** — `api.lever.co/v0/postings/{company}?mode=json` · **Ashby** — `api.ashbyhq.com/posting-api/job-board/{company}`
- **SmartRecruiters** — `api.smartrecruiters.com/v1/companies/{company}/postings` (server-side `country`/`city` filter) · **Workable**, **Recruitee** (public, per-company)
- German-market extras (later): **softgarden** (needs channel/token), **Teamtailor** (needs a free key)

**Layer 2 — Remote feeds (OPTIONAL; only for remote-heavy niches):** WeWorkRemotely, Jobicy, Remotive. ⚠️ Validated as **mostly noise** for a specific role (Mina: 0/10 real UX) — the AI must filter hard, so keep these secondary.

**Discovery-only:** Bundesagentur (names, no descriptions, ToS-restricted) — used offline to seed company lists, never a live feed.

**Rejected / not free:** Adzuna (free tier = testing-only), Indeed / StepStone / LinkedIn / Xing (no free API; scraping only).
**To test:** **Jooble** (free key → aggregates thousands of sources incl. LinkedIn/Indeed; thin text though).

## Validation (playground tests, Docker, 2026-07-05 → -09)

- **Coverage** — Common Crawl → **1,066 Personio.de companies**; ~240 Munich / ~55 Bodensee on Personio alone. Munich strong, Bodensee decent.
- **Common schema + dedup** — all sources map to one schema, all with full descriptions; no shared id → dedup by company+title+location.
- **Accuracy** — LLM scored real jobs correctly: rejected non-matches (incl. *Instructional Designer* ≠ UX), penalized wrong seniority/location.
- **Scale** — full daily run for one niche ≈ **1.4 min** (poll 1,066 cos in ~40s + a few dozen LLM reads). Poll shared across niches → non-issue on one GPU.
- **End-to-end, real dashboards with links** — **Mina** (junior UX, Munich): full universe → 20 candidates → **2 strong**. **Tom** (senior fullstack, Bodensee + German-remote): → 132 candidates → **~22 strong**. Same code path; per-user location rules honored (Tom's German-only rule correctly excludes global remote feeds).
- **Niche-size truth** — narrow niches are genuinely tiny markets (junior UX Munich ≈ 2–8 jobs even at full coverage) → hence the **Broaden** option.
- **Sources** — SmartRecruiters (country filter), WeWorkRemotely, Jobicy tested working & free; remote feeds confirmed noisy for niche roles → **ATS-first** decided.

## Data model

7 tables. `companies` + `jobs` are **shared** (fetched once for everyone); `niches` + `matches` are **per-user** (where personalization lives).

```
users          account (via Keycloak)
cv             user's CV: file + parsed text + level
niches         user's search: role, keywords, place, target level
companies      shared universe: slug, ATS type, region
jobs           per company: title, description, location, remote, language, url, posted, status
matches        per niche: job, fit_score, verdict, why, seen, applied
cover_letters  per (user, job): generated text
```

Relations: user 1–1 cv · user 1–* niches → matches → jobs · company 1–* jobs · (user, job) → cover_letter.
Scoring is **per-user** using the CV (falls back to niche criteria when no/unreadable CV).
